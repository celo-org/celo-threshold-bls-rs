# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Releases are git tags on this repository; the crates are not published to crates.io.

## [Unreleased]

### Added

- npm: The `@celo/blind-threshold-bls` npm package now lives in this repository under `bindings/js`, imported from the standalone `celo-org/blind-threshold-bls-wasm` repo. The wasm binary is built fresh by wasm-pack instead of vendored, and defects carried over from the old repo were fixed: the README demonstrated a blind-signing flow whose unblinded result never verifies, an example required a nonexistent package name, `package.json` listed a file wasm-pack does not emit, and examples were excluded from the published tarball. CI now builds the package and runs its jest suite, including new negative tests for the throwing paths ([#203](https://github.com/celo-org/celo-threshold-bls-rs/pull/203)).
- jvm: Added a JNI binding surface to `threshold-bls-ffi`, enabled by the `jvm` Cargo feature: a single `Java_org_celo_BlindThresholdBls_verify` function that verifies a BLS signature from Java. The native call runs under `catch_unwind`, so malformed keys or signatures return `false` instead of panicking across the FFI boundary into the JVM ([925abd1](https://github.com/celo-org/celo-threshold-bls-rs/commit/925abd1), [#199](https://github.com/celo-org/celo-threshold-bls-rs/pull/199), [9cfed53](https://github.com/celo-org/celo-threshold-bls-rs/commit/9cfed53)).
- wasm: Added a `wasm-debug` Cargo feature that enables `console_error_panic_hook`, so wasm panics surface as messages in the JS console ([925abd1](https://github.com/celo-org/celo-threshold-bls-rs/commit/925abd1)).
- ffi: `cross/threshold.h` now defines `SEED_LEN`, the number of seed bytes `keygen` and `blind` require, so a caller can size the buffer from the same constant the library checks against instead of from prose in a comment ([#219](https://github.com/celo-org/celo-threshold-bls-rs/pull/219)).
- ffi: `cross/threshold.h` now defines the byte lengths the C API works in — `PUBKEY_LEN`, `PRIVKEY_LEN`, `SIGNATURE_LEN` and `PARTIAL_SIG_LENGTH`. They were crate-private, so a caller had to hardcode them: `free_vector` needs the length of the buffer `serialize_pubkey` and friends hand back, and `combine` splits its flattened input into `PARTIAL_SIG_LENGTH` chunks, which a caller cannot build without knowing the value ([#216](https://github.com/celo-org/celo-threshold-bls-rs/pull/216)).

### Changed

- sig: `BlindScheme::blind_msg` returns `Result<(Self::Token, Vec<u8>), Self::Error>` rather than panicking when the message cannot be mapped to the curve or the blinded point cannot be serialized. Breaking for git consumers of the crate, who now have to handle the error; neither failure is reachable in practice ([#219](https://github.com/celo-org/celo-threshold-bls-rs/pull/219)).
- core: Migrated the cryptography from the unmaintained zexe/algebra libraries to arkworks, then upgraded through arkworks 0.3, 0.4, 0.5 and 0.6. Signature and key byte formats are unchanged (48-byte G1, 96-byte G2, 32-byte scalars), so existing signatures and keys remain valid. Breaking for consumers using the crates via git: the curve module was renamed from `zexe` to `bls12377`, rand/rand_core moved to 0.8/0.6, and the crate's `bls12_377`, `bls12_381` and `default` Cargo features were removed, so builds declaring them fail ([a13e74b](https://github.com/celo-org/celo-threshold-bls-rs/commit/a13e74b), [#136](https://github.com/celo-org/celo-threshold-bls-rs/pull/136), [af3b2a1](https://github.com/celo-org/celo-threshold-bls-rs/commit/af3b2a1)).
- core: Removed the bls-crypto dependency, inlining the Blake2s/Blake2X hasher, the signature domain constant, and the FFI `Buffer` struct; drops 37 transitive dependencies. The crate error type `ZexeError` was renamed to `BLSError` with flattened variants, and the unused `CurveError` enum was removed — breaking for git consumers matching on error types ([#157](https://github.com/celo-org/celo-threshold-bls-rs/pull/157)).
- ffi: The C ABI is now gated behind an explicit `ffi` Cargo feature instead of being compiled whenever the `wasm` feature was off; the mobile cross builds enable it by default ([925abd1](https://github.com/celo-org/celo-threshold-bls-rs/commit/925abd1), [0025630](https://github.com/celo-org/celo-threshold-bls-rs/commit/0025630)).
- ffi: The Android shared libraries are linked with 16 KiB page-size alignment (`-Wl,-z,max-page-size=16384`), so they load on Android 15+ devices that use 16 KB memory pages ([19120ae](https://github.com/celo-org/celo-threshold-bls-rs/commit/19120ae)).
- ffi: Pinned the iOS static libraries to deployment target 15.2 (previously they inherited Rust's default, which drifts across toolchain releases) and documented the mobile floors: Android API 24, iOS 15.2 ([daf3923](https://github.com/celo-org/celo-threshold-bls-rs/commit/daf3923)).
- ffi: `free_vector` now takes a `const uint8_t *`, so a caller can hand `Buffer::ptr` straight back without casting away the qualifier. The symbol and calling convention are unchanged, and existing callers still compile ([#216](https://github.com/celo-org/celo-threshold-bls-rs/pull/216)).
- build: The toolchain is pinned via `rust-toolchain.toml`, currently to Rust 1.97, and the crate manifests track it as the MSRV ([#137](https://github.com/celo-org/celo-threshold-bls-rs/pull/137), [2ba8e0b](https://github.com/celo-org/celo-threshold-bls-rs/commit/2ba8e0b), [#202](https://github.com/celo-org/celo-threshold-bls-rs/pull/202), [#222](https://github.com/celo-org/celo-threshold-bls-rs/pull/222)).
- all: Both crates moved to edition 2024. The code needs Rust 1.88 or newer; the declared MSRV stays at the pinned toolchain, 1.97. No API, behaviour or wire format changed, and the C ABI's exported symbols and generated header are byte-identical ([#222](https://github.com/celo-org/celo-threshold-bls-rs/pull/222)).
- build: Tightened the release profile (incremental off, `codegen-units = 1`) for smaller shipped binaries across all release artifacts ([4385993](https://github.com/celo-org/celo-threshold-bls-rs/commit/4385993)).
- build: Release artifacts are built with a single justfile (`just wasm|jvm|android|ios`), replacing the previous Makefiles; all recipes except `ios` build in Docker ([#191](https://github.com/celo-org/celo-threshold-bls-rs/pull/191)).
- build: Every cargo invocation in the justfile and in CI passes `--locked`, so a build resolves the committed `Cargo.lock` and fails rather than silently picking up a newer patch release. A dependency change is now a commit, `cargo audit` scans the graph that was built, and two builds of the same commit see the same sources. The wasm package is built through the new `just wasm-pkg` recipe, which gates on `cargo metadata --locked` because wasm-pack resolves dependencies itself before cargo sees the flag. The build image verifies the Android NDK and wasm-pack downloads against pinned SHA-256 checksums, and CI installs the same wasm-pack version the release image uses instead of the newest release ([#224](https://github.com/celo-org/celo-threshold-bls-rs/pull/224)).

- core: `GT`, the pairing's target group, no longer implements `Element`, and `PairingCurve::GT` is bounded by `Eq + Debug` — all a pairing check needs, and all this crate ever did with one. The impl existed to satisfy the bound and had to invent an additive identity for a multiplicatively written group: `GT::zero()` returned `One::one()`, so `GT::zero() == GT::one()` held, and `GT::add` multiplied. Nothing called any of it. Breaking for git consumers implementing `PairingCurve` for another curve, who now have less to implement, and for anyone calling `Element` methods on a `GT`.
- core: `Element::new` is gone; the group identity is `Element::zero`, which is now the trait's required method rather than a defaulted alias for it. The two names meant the same value — `poly.rs` reached for both — and only one of them said which value. Breaking for git consumers, mechanically: `X::new()` becomes `X::zero()`.
- core: `Poly::set` takes an `Idx` rather than a `usize`, matching `Poly::get`. Breaking for git consumers.
- core: `BlindThresholdError` no longer requires its error parameter to be `'static`, and `ThresholdError::PolyError` gains a `From` conversion. Neither breaks existing code.
- core: `sig::bls` is `#[doc(hidden)] pub` so that `BLSScheme`, which rustc names when an out-of-crate scheme family is missing it, is a path the implementor can import. Following the suggestion previously produced `E0603: module bls is private`.

### Removed

- core: Removed the dkg-core and dkg-cli crates and the Solidity DKG contract entirely — breaking for anyone depending on them via git. Only threshold-bls and threshold-bls-ffi remain; the README records the last commit that still contained the DKG code ([a911f40](https://github.com/celo-org/celo-threshold-bls-rs/commit/a911f40), [1a010e6](https://github.com/celo-org/celo-threshold-bls-rs/commit/1a010e6)).
- core: Removed the BLS12-381 curve and its schemes (and the paired/ff/groupy dependencies); BLS12-377 is now the only supported curve. Breaking for any git consumer that used the BLS12-381 instantiations ([a13e74b](https://github.com/celo-org/celo-threshold-bls-rs/commit/a13e74b), [#136](https://github.com/celo-org/celo-threshold-bls-rs/pull/136)).
- core: Removed the unused ECIES module (`threshold_bls::ecies`), which existed only for the removed DKG crates and was exposed by no binding; drops the chacha20poly1305, hkdf and sha2 dependencies plus 10 transitive crates. Breaking for git consumers ([#196](https://github.com/celo-org/celo-threshold-bls-rs/pull/196)).
- core: Removed the `PrimeOrder` trait and its `in_correct_subgroup` method from the group API. Nothing called it, and its only implementation (on GT) answered true for the identity element — exactly the value a subgroup check exists to reject ([f56c688](https://github.com/celo-org/celo-threshold-bls-rs/commit/f56c688)).
- ffi: Dropped the arm-linux-androideabi (armeabi/ARMv5) Android target from the mobile builds; it has been unsupported by the NDK since r17 and is below the consumer's minimum of Android API 24 ([a932e4b](https://github.com/celo-org/celo-threshold-bls-rs/commit/a932e4b)).

### Fixed

- curve: Reimplemented the try-and-increment hash-to-curve during the arkworks migration to match the original algebra-core behavior exactly. The bls-crypto "compat" path it would otherwise have used has two flag-extraction bugs that make it produce different curve points, so pre-migration signatures would have failed verification. Known-answer test vectors pin the G1 and G2 hash-to-curve outputs ([#136](https://github.com/celo-org/celo-threshold-bls-rs/pull/136), [d1a192c](https://github.com/celo-org/celo-threshold-bls-rs/commit/d1a192c), [4f260f3](https://github.com/celo-org/celo-threshold-bls-rs/commit/4f260f3)).
- ffi: Mobile cross builds produced Android `.so` and iOS `.a` libraries with no exported symbols: the build passed an empty feature list through to a `--no-default-features` build, so the C ABI was never compiled in. Cross builds now default to the `ffi` feature, and overriding the feature list still works ([0025630](https://github.com/celo-org/celo-threshold-bls-rs/commit/0025630)).
- ffi: The three binding surfaces (wasm, ffi, jvm) are now gated by independent `#[cfg]` attributes instead of a first-match `cfg_select!`, so enabling several features together compiles all of them. Previously CI's `--all-features` test and lint jobs compiled only the wasm module, so the C ABI and JNI code they were meant to cover was never tested or linted ([#200](https://github.com/celo-org/celo-threshold-bls-rs/pull/200)).
- ffi: Fixed a panic in the C ABI's `Buffer::from` when handed an empty slice, and a `dangerous_implicit_autorefs` soundness issue in `share_ptr` ([#157](https://github.com/celo-org/celo-threshold-bls-rs/pull/157)).
- ffi: `cross/threshold.h` is generated from `src/ffi.rs` by cbindgen and checked by CI, replacing a hand-maintained copy that had drifted from the library it describes. `keygen` was declared to take a `Keypair *` where the library writes through a `Keypair **`, so the only prototype-conforming C call wrote a heap pointer through whatever the caller supplied; `blind`, `serialize_pubkey`, `serialize_privkey` and `serialize_sig` were declared `void` although they return `bool`, so callers silently dropped failures; and `sign_blinded_message`, `partial_sign_blinded_message`, `partial_verify_blind_signature` and `destroy_keypair` were absent from the header entirely. Breaking for the C ABI surface: the blinding factor handle is now named `BlindingFactor`, previously `Token_PrivateKey`; the share and polynomial handles are gone entirely, since those now cross as bytes (see the next entry) ([#216](https://github.com/celo-org/celo-threshold-bls-rs/pull/216)).
- ffi: The C ABI's threshold operations can be called. `partial_sign`, `partial_sign_blinded_message`, `partial_verify` and `partial_verify_blind_signature` took opaque `Share`/`Poly` handles that no export produced, so no C caller could reach them at all — the last producer went away when `threshold_keygen` became test-only. They now take the share and the public polynomial as serialized bytes, matching the WASM surface and `combine`. Breaking for the C ABI surface, though nothing could have been calling them ([#216](https://github.com/celo-org/celo-threshold-bls-rs/pull/216)).
- ffi: The six serialize and deserialize functions honour the NULL contract their documentation advertises instead of dereferencing the pointer. `deserialize_pubkey(NULL, &out)` previously read 96 bytes from address zero ([#216](https://github.com/celo-org/celo-threshold-bls-rs/pull/216)).
- ffi: The C ABI enforces the pointer and ownership contracts its documentation states. Every `Buffer` argument now goes through one accessor that rejects a NULL `Buffer` and a buffer claiming a length behind a NULL pointer, instead of handing both to `slice::from_raw_parts`; the six destructors and `free_vector` ignore NULL rather than freeing it; `public_key_ptr` and `private_key_ptr` return NULL for a NULL keypair, and the header now says they borrow from the keypair and must not be freed on their own. Breaking for the C ABI surface: `keygen` returns `bool` instead of `void`, so a caller can tell that it wrote nothing ([#217](https://github.com/celo-org/celo-threshold-bls-rs/pull/217)).
- all: `combine` rejects a flattened input whose length is not a whole number of `PARTIAL_SIG_LENGTH` chunks, on both the C and the wasm surfaces. Chunking a remainder cuts the last chunk out of the middle of two partial signatures and hands `aggregate` one more partial than the caller supplied. Such input was already refused, but by the deserializer failing on the short tail; the wasm error now names the length instead ("expected a multiple of 60 bytes, one per partial signature, got 61"). `combine` also gained a `try_combine` inner function, so its error paths are testable outside wasm.
- ffi: `deserialize_pubkey`, `deserialize_privkey` and `deserialize_sig` are told how many bytes they were given. Each read `PUBKEY_LEN`, `PRIVKEY_LEN` or `SIGNATURE_LEN` bytes from a pointer that carried no length, so a caller holding a shorter buffer had no way to say so and the read ran past the end of their allocation; the header did not state how many bytes were read either. They now take a `Buffer`, like every other input on this surface, and refuse any length but the exact one. Breaking for the C ABI surface: pass `&(Buffer){bytes, PUBKEY_LEN}` where a bare pointer went before ([#227](https://github.com/celo-org/celo-threshold-bls-rs/pull/227)).
- ffi: Buffers handed to C are allocated at exactly the length reported for them, so `free_vector` releases the whole allocation. It rebuilds the allocation from the pointer and length alone, which held only because bincode happens to allocate exactly-sized vectors; a `Vec` is only guaranteed to allocate at least the capacity asked for. The three `serialize_*` functions also refuse to hand out a buffer whose length differs from the constant in the header that the caller has to free it with ([#217](https://github.com/celo-org/celo-threshold-bls-rs/pull/217)).
- ffi: `keygen` and `blind` return false for a seed shorter than `SEED_LEN` instead of panicking. The seed used to be sliced to length, and a panic crossing `extern "C"` aborts the process the library was called from. It is refused rather than zero-padded, which would draw key material from less randomness than the caller supplied bytes for ([#219](https://github.com/celo-org/celo-threshold-bls-rs/pull/219)).
- wasm: `keygen`, `blind`, `thresholdKeygen` and `Keys.getShare` throw instead of panicking when the caller passes an argument they cannot use, which in wasm traps and poisons the instance. A seed shorter than 32 bytes was sliced to length, `getShare` indexed the share vector unchecked with `numShares` as the caller's only guard, and `thresholdKeygen` asked for a polynomial of degree `t - 1`, which at a threshold of zero is `usize::MAX`. `thresholdKeygen` also caps the group at 1024 shares, far above any real threshold group, so a mistyped `n` fails with a message instead of asking the allocator for gigabytes. Callers already passing a 32-byte seed, an in-range index and a threshold between 1 and `n` see no change ([#219](https://github.com/celo-org/celo-threshold-bls-rs/pull/219)).
- wasm: Corrected the `verifyBlindSignature` documentation: it pairs against the supplied blinded message point without hashing, so it proves nothing about the plaintext that was blinded; the docs previously claimed it checks the signature on the message hash. Users needing plaintext verification are pointed at `verify` ([c7cb3fc](https://github.com/celo-org/celo-threshold-bls-rs/commit/c7cb3fc)).

### Security

- poly: A public polynomial with no coefficients no longer deserializes. It was a bare bincode length prefix any caller could send, and it reached `Poly::degree()`, which computed `self.0.len() - 1` and answered `usize::MAX` in release builds, and `Poly::public_key()`, which indexed an empty vector. PR #216 made it reachable from the shipped C ABI, where `partial_verify` began taking the polynomial as caller-supplied bytes rather than as an opaque handle no C caller could construct. Nothing verified under it before — the identity public key check rejected it at the pairing — but that safety lived in another module rather than in the type. Breaking for git consumers of `threshold-bls`: `From<Vec<C>> for Poly<C>` is now `TryFrom<Vec<C>>`, since a fallible conversion cannot coexist with the blanket `From` impl.

- sig: Signature verification now rejects the identity point for both the public key and the (blinded) message operand. Previously an identity public key made the pairing equation hold for any message, so an identity signature under it verified anything; and because blind verification takes the message point from the wire, a blinded message set to the identity point allowed forging a blind signature that verified under any honest public key. The check lives in the shared pairing step, so `verify`, `partial_verify`, `blind_verify` and `verify_blind_partial` all inherit it across every binding. The compressed identity still deserializes (matching the IETF spec); only verification rejects it ([#205](https://github.com/celo-org/celo-threshold-bls-rs/pull/205)).
- sig: Signature aggregation and share recovery now reject a zero threshold and require the threshold number of distinct share indices. Previously `aggregate(0, &[])` interpolated over an empty set and returned the identity element as a valid-looking signature from no inputs, and duplicate share indices silently shrank the interpolation set below the threshold, producing a wrong signature in release builds (debug builds panicked) ([#206](https://github.com/celo-org/celo-threshold-bls-rs/pull/206)).
- poly: Fixed an integer wrap on the maximum share index: polynomial evaluation and share recovery computed the evaluation point as index + 1 in u32, so a share at `Idx::MAX` wrapped to point zero. In release builds a share submitted at that index annihilated every other Lagrange term and its value was returned verbatim in place of the honest shares during recovery; debug builds panicked on the caller-supplied index. The addition is now done in u64, leaving all valid indices unchanged ([#205](https://github.com/celo-org/celo-threshold-bls-rs/pull/205)).
- serialization: Capped bincode deserialization input at 1 MiB via new bounded helpers `threshold_bls::serialization::{deserialize, deserialize_from}`, now used at every deserialization site. Previously the attacker-controlled u64 length prefix in a crafted polynomial or partial signature passed over WASM, the C ABI, or JNI could trigger a multi-exabyte Vec pre-allocation and OOM the host process; such inputs are now rejected with an error. Wire formats for public polynomials, private-key shares, and partial signatures are pinned by new round-trip test vectors ([405b3a1](https://github.com/celo-org/celo-threshold-bls-rs/commit/405b3a1)).
- ffi: Removed `threshold_keygen` (and its `Keys` struct, accessors, and `destroy_keys`) from the C ABI, demoting it to a Rust test helper. The function took a Rust `&[u8]` fat pointer across `extern "C"`, which has no defined C ABI: any C caller declaring it with `const uint8_t*` would misread the slice length and read out of bounds. cbindgen had always omitted it from `threshold.h`, so no legitimate C caller existed; the stale hand-written declarations were pruned from the header. The WASM `thresholdKeygen` export is unaffected. Breaking for the C ABI surface ([67ae846](https://github.com/celo-org/celo-threshold-bls-rs/commit/67ae846)).
- curve: The BLAKE2X hash helper now rejects output lengths that do not fit the format's 16-bit digest-length field, including the reserved 0xffff unknown-length value; oversized requests previously truncated silently. Unreachable through current callers, which only hash to point-sized outputs. Also documented the cofactor-clearing soundness argument for hash-to-curve and added a debug assertion that hashed points land in the prime-order subgroup ([27aee13](https://github.com/celo-org/celo-threshold-bls-rs/commit/27aee13), [a6650eb](https://github.com/celo-org/celo-threshold-bls-rs/commit/a6650eb)).
- build: Updated the locked rand crate to 0.8.6 in response to a security advisory (lockfile-only change, affects the built artifacts) ([b9550f1](https://github.com/celo-org/celo-threshold-bls-rs/commit/b9550f1)).
